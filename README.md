# GGVAULT — магазин игровой валюты

Демонстрационный интернет-магазин игровой валюты: React 19 + Vite на фронте,
Python (FastAPI + SQLAlchemy ORM + SQLite) на бэкенде.

## Возможности

- Каталог из 12 игр и 81 товара: 47 пакетов валюты, подписки, скины и прокачка
- Поиск, фильтр по категориям и сортировка
- Карточка игры с выбором пакета, количества и игрового ника
- Корзина-drawer с промокодами (`GG10`, `NEW15`, `VAULT20`)
- Оформление заказа с валидацией формы и выбором способа оплаты
- Пользователи и заказы в SQLite через ORM (SQLAlchemy), роли: user / operator / admin / booster
- История заказов с проверкой статуса и повтором покупки
- Браузерные уведомления клиенту, когда заказ выполнен (пока вкладка сайта открыта)
- Заявка на возврат доставленного заказа: выбор причины из списка и комментарий
- Рассмотрение заявки сотрудником: подтверждение возврата или отказ с указанием
  причины отказа и комментария — клиент видит их в своём заказе
- Центр заказов для сотрудников: назначение операторов, смена статусов
- Администратор добавляет товары и новые игры в каталог через центр заказов
- Серверная проверка цен, скидок и статусов заказов по единому каталогу
- Светлая и тёмная темы, адаптивность, уведомления (toasts)

## Запуск

Бэкенд (в первом терминале) — при первом запуске сам создаёт БД `server/ggvault.db`
и заполняет её сотрудниками:

```bash
pip install -r requirements.txt
npm run server        # uvicorn слушает 0.0.0.0:8000
```

Фронтенд (во втором терминале):

```bash
npm install
npm run dev           # vite слушает 0.0.0.0:5173
```

API-документация (Swagger): http://127.0.0.1:8000/docs

### Защита от перегрузки

`server/ratelimit.py` ограничивает всплески запросов на уровне приложения:

- `/api/login` и `/api/register` — не больше 5 запросов в минуту на IP
  (каждая попытка подбора пароля нагружает CPU через PBKDF2);
- остальные `/api*` — не больше 60 запросов в минуту на IP;
- тело запроса больше 1 МБ отклоняется с кодом 413.

Лимитеры хранят счётчики в памяти процесса: при запуске с `--workers`
лимит умножается на число воркеров, а пользователи за одним NAT делят
общий лимит. Для «боевого» запуска без `--reload` есть `npm run server:prod`.

### Доступ из локальной сети

Оба сервера по умолчанию слушают все интерфейсы (`0.0.0.0`), поэтому сайт доступен
с других устройств в той же сети по IP-адресу компьютера:

- фронтенд: `http://<IP>:5173`
- API / Swagger: `http://<IP>:8000/docs`

Узнать IP: `ipconfig` (Windows) или `ip addr` (Linux). Если браузер на устройстве
открывается, а страница не грузится, проверьте брандмауэр — разрешите входящие
подключения к портам 5173 и 8000.

Собранная версия (`npm run build` + `npm run preview`) тоже работает в сети:
`http://<IP>:4173`, запросы `/api` проксируются на бэкенд.

## Структура

```
server/        # FastAPI + SQLAlchemy: модели, авторизация, REST API
  main.py      #   маршруты и сидирование сотрудников
  catalog.py   #   загрузка каталога цен, промокодов и причин возврата/отказа
  models.py    #   ORM-модели: User, Session, Order, OrderItem
  database.py  #   подключение к SQLite (WAL, busy_timeout)
  ratelimit.py #   лимиты запросов на IP и размера тела (защита от всплесков)
  security.py  #   хеширование паролей и токены сессий
shared/
  catalog.json # единый источник цен, промокодов и причин возврата/отказа
src/
  components/   # шапка, подвал, карточки, корзина, иконки, toasts
  data/         # игры, промокоды, причины возврата и отказа из shared/catalog.json, отзывы, FAQ
  pages/        # главная, каталог, игра, оформление, заказы, FAQ, контакты
  store/        # контекст корзины, авторизации и заказов (через /api)
  styles/       # дизайн-система и адаптивные стили
  utils/        # форматирование цен, дат и склонений
```

Цены, промокоды и списки причин возврата/отказа меняются только в `shared/catalog.json` —
сервер не доверяет значениям из запроса, пересчитывает стоимость заказа
самостоятельно и принимает только причины из каталога.

Каталог пополняется администратором через `/admin` (POST `/api/games` и
`/api/games/{id}/products`): сервер дописывает игру или товар в тот же
`shared/catalog.json` и сразу видит их при расчёте заказов. Фронтенд в
режиме разработки (`npm run dev`) подхватывает изменения сам, а для
собранной версии нужен повторный `npm run build`.

Все названия игр и цены вымышлены и используются только в демонстрационных целях.
